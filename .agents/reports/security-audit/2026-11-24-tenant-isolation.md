# Tenant isolation security review

Review started 2026-11-24. Base revision `72d7f360` matched GitLab's `main` during the review. Verdict **findings open**.

## Findings by severity

No critical or high cross-Biz-E-tenant disclosure was confirmed in the paths reviewed. The suite and source inspection establish specific controls. Route-by-route isolation coverage remains incomplete.

| ID | Severity | Evidence and impact | Status and test |
| --- | --- | --- | --- |
| TI-01 | Medium | [Xero OAuth callback](../../../app/features/crm/routes/oauth_routes.py#L122), [token storage](../../../app/features/crm/services/xero_oauth_service.py#L118) and [Xero client](../../../app/features/crm/services/xero_api_client.py#L76). During a multi-account Xero connection, the callback commits the first returned account as an active connection for Biz-E org B before its administrator confirms which Xero account belongs to B. A Xero operation started in that interval can use the first account's credentials and tenant ID. If that account belongs to A and the connecting Xero identity has access to both, records could be imported into B. The evidence is a source trace. This is an external account selection issue, distinct from ordinary Biz-E org ID scoping. | **Open.** Needs a pending connection state that preserves the active connection until selection and binds selection to the initiating user and organisation. Live provider behavior was outside the local audit. No reproduction test or expected-failure marker was added. |
| TI-02 | Medium | [Xero revocation logging](../../../app/features/crm/services/xero_oauth_service.py#L267) formerly passed the upstream exception into a credential-handling log statement. A mocked transport failure proved the exception reached the logger. If diagnostics contain sensitive details, these could reach operators with log access. No tenant-to-tenant log access was identified. | **Fixed.** The event carries the organisation ID and exception class. `test_disconnect_logs_only_safe_revocation_failure_metadata` failed on the original code and verifies that local disconnect still completes. |
| TI-03 | Low | [Wine trace CSV](../../../app/features/compliant/modules/nz_alcohol/wine/trace.py#L154) omitted tab and carriage return from the spreadsheet formula prefix check used in the other exports. Tenant-entered text can travel in a downloaded trace to a spreadsheet used by an auditor. The test uses ordinary text with leading control characters and verifies the raw parsed CSV cells. | **Fixed.** `test_trace_csv_quotes_text_with_leading_control_characters` failed on the original serializer. Spreadsheet execution was outside the test scope. |
| TI-04 | Info | [Global tenant filter](../../../app/core/db/tenant_filter.py#L46). Tenant context scopes ORM statements on `TenantScoped` models. Core SQL needs explicit filters. Auth bootstrap can legitimately have no tenant context, and already-loaded ORM instances can be returned from the identity map without another query. These constraints matter for background jobs and for code that deliberately leaves tenant scope. No cross-tenant request path was established from these constraints during this review. | **Open coverage item.** `tests/test_tenant_filter.py`, `tests/test_tenant_filter_spike.py` and the flush-guard tests pin the existing safeguards. |

The composed local app exposed 562 URL rules. The route inspection found 49 public, 511 with a standard auth/permission wrapper or portal guard, and three with other handling, counting unique non-HEAD/non-OPTIONS endpoint/method pairs. The three were `auth.cancel_2fa` (public session cleanup), `costing.static` (built-in static handler), and `oauth.authorize` GET (explicit sign-in branch before rendering tenant consent). Route classification is also tested by `test_every_route_has_an_explicit_rule`. The baseline browser route map counted all methods as covered on 208 of 544 considered rules and showed gaps on 336. That map measures route references, which cannot establish tenant isolation by itself.

Source checks covered tenant filters and flush guards, the request session lifecycle, CSRF exceptions, download boundaries, tenant-scoped raw SQL in the change feed and ZIP summaries, and the system-findings cache's org-scoped lookups, locks and updates. The broad review used static and sample runtime checks. It did not establish comprehensive per-query coverage, database row-level security, or controls at a deployed reverse proxy. All runtime checks used local test data.

- `tests/test_multi_tenant_api.py` is a manual script with a cleanup command and contains zero pytest cases. Automated tenant coverage comes from the files mapped above.
